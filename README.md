# NightGuard — 夜间癫痫发作监测判据引擎

在公开临床数据上实测过的夜间发作报警算法。**不是产品,是一个诚实的算法验证结果。**

许可:[MIT](LICENSE)　语言:Python 3.11+（引擎只依赖 numpy）　测试:292 项全通过

---

## 一句话

**致命级发作（继发全身化 + 阵挛期,与 SUDEP 相关）23 次检出 23 次,代价是误报 6.70 次/10 夜。**

这两个数字必须一起看。只报前者是误导。

单位换算（致命级队列 242h / 38夜 = 6.37 小时/夜）:
`6.70 次/10夜` = `0.105 次/小时`。注意**它不等于 0.67 次/小时** ——
次/夜 和 次/小时 混用会把结论说错 6 倍。

---

## 先说做不到什么

这部分放在最前面,因为它比成绩重要。

| 做不到 | 实测证据 |
|---|---|
| **抓不到"隐匿发作"**（不抽搐、只僵住发呆的那类） | 发作时心率确实升 1.0–1.83 倍,但背景有 **10.8% 的时间**也超过自身 1.5 倍。换传感器无用,是信噪比问题 |
| **误报降不到 0.05 次/小时**（目标 = 3.2 次/10夜,实测 **6.70** 次/10夜 = 0.105 次/小时,**差 2.1 倍**） | "时间/分级/新信息"三种货币全部用完后,6.70 次/10 夜是硬下限 |
| **没验证血氧和体温** | 所用数据集根本没有这两个通道 |
| **呼吸只能从心电反推** | 覆盖率 72%,且单独增益仅 0.7 个点 |
| **不是无穿戴** | 全部结论基于佩戴式传感器（胸贴 + 耳后贴片） |
| **样本量小** | 致命级发作仅 23 次。要达到 recall ≥99% 的认证口径需 161 次 |

## 三个最有用的结论（给后来者省时间）

**1. 绝对阈值一定失效,必须个体化。**
"心率 > 120 报警"这种规则在真实数据上直接崩:有患者睡眠期心率中位数就是 130。
22 位患者中 13 位的发作分数低于**自身**背景 P95。
正确做法:个体基线**并列**而非替换全局特征（替换式归一化会抹掉共同信号:0.6767 → 并列后 0.7635,误报降 34%）。

**2. 分级报警里不能有"静默档"。**
我们实测过:把低置信事件放进不响铃档,**29 次致命级发作有 26 次落在了静默档**,响铃档只覆盖 10%。
所以本仓库 `engine/tiers.py` 里 `SILENT_TIERS` 恒为空、`rings()` 恒 True —— 分级只决定**怎么响**,不决定**是否响**,并由 `tests/test_gyro_tiers.py` 锁死。

**3. 瓶颈在特征判别力,不在融合策略或模型。**
五通道并集 = 体动 ∪ 心率 = 23/23,新增通道独家救回 **0** 次发作。
被救回的发作在"角速度占比 / 体动峰 / 心率峰"三维上**全部落在误报分布内部**。
别再试多路投票、阈值微调或换模型 —— 先换能分开"翻身"和"阵挛"的信息。

## 已验证的死路（别重走）

- 响铃后按持续性自动撤回 → 任何能撤回误报的门槛都会误撤真发作
- 事件级封顶 / 预算排序 → 单调标量门槛会静默吃掉真发作（曾压掉 2154 次响铃,把 22/22 伪装成 16/22）
- LLM 进实时判决路径 → 只否决 0.9% 的误报,只能做事后过滤
- 体位门（倾角）在院内数据上 → 发作本身污染重力估计,需家庭数据才测得准

## 评估口径（复现时必须对齐,否则数字不可比）

1. **按发作类型分层**:致命级（`sz_foc_f2b` / `sz_gen_*`）与非致命（tonic/clonic/myoclonic）必须分开报,混在一起会把 20/23 平均成 65%
2. **事件级和响铃级两把尺子一起报**:9 个误报事件可以等于 2846 次响铃
3. **用留一法,不报全集最优**:17 个正样本配 6 个旋钮,全集"零漏报"被 LOO 推翻过两次
4. **背景时长要对齐**:2h → 12h 背景,同工作点误报从 1.15 涨到 1.55/h
5. **缺通道的记录不能静默剔除**:曾有 3 次致命级发作因缺电极从分母消失,31 被当成 28
